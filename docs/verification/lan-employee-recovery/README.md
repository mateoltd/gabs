# Employee received-draft recovery

Status: locally verified, 18 September 2026. Scope: SDK-05-LAN-EMP-REC, not full SDK-05 or release parity.

## Behavior and boundaries

- Company employees use the existing Received drafts interface with an explicit module relay grant and resource read or queued-operation permission. The main process obtains current policy and verifies signed contracts. It filters foreign-account envelopes and inaccessible modules/resources before returning contents, archive byte usage or counts. A peer-status capability cannot authorize recovery.
- Offline recovery uses previously prepared protected signed relay leases and current known company policy. Scope, issuer, package identity, current grants, expiry and clock history remain authoritative in native main. Connected administrators preserve quarantine inspection; offline administrators use the same scoped grants as employees.
- Local archive, restoration, file export/import and confirmed copy deletion never finalize corporate changes. Files contain no accepted-state claim. Protected uncertain outcomes and original idempotency keys survive archive/file recovery. Submission independently requires connectivity, a valid original queued contract and server permission.
- Policy and grant checks run again before receipt disclosure/actions and after native dialogs. Query context includes account, workspace and authorization state; failed or aborted queries cannot retain revoked previews. Read and relay permission changes are checked even when a policy revision has not changed.
- An intermittent native restart exposed a late wildcard-route redirect overriding a newer Settings click while the catalog loaded. `RouteRedirect` now checks the active router location against the retained route before redirecting. A deterministic browser test holds the transition while catalog loading finishes, verifies the newer Settings navigation survives, and separately verifies current unknown routes still redirect. Rendering styles and transition timing are unchanged.
