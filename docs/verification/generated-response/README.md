# SDK-04: generated responses and retained journal contracts

17 September 2026. The generated host/cache/journal gate passed local acceptance. Together with the evidence in the [SDK-04 map](../../sdk-04-acceptance.md), this completes SDK-04's scoped documentation, schema UI and typed composition work. Whole-platform parity, full UI-kit/accessibility acceptance and final UI approval remain open.

## Behavior

- Generated get/list/create/update/archive requests validate returned resource data and metadata against the corresponding verified module version before caching or accepting a result. Cached pages are validated before rendering, including corrupt null values. An unavailable page displays an error and an unavailable count instead of inventing an empty result. A previously validated offline page remains usable after an online read fails.
- An uncertain generated save retains its original call, input and idempotency key while its editor remains mounted. An uncertain archive exposes a retry of the same request. Neither a malformed reply nor a timeout/rate-limit response authorizes a fresh mutation key.
- Queued work retains the complete signed package and trust key for its original module/version, atomically with the journal. Existing chunked artifact storage bounds individual persistence records and retains original packages through updates and uninstall. Accepted or superseded entries release their package references; orphan collection removes unused chunks on the next mutation.
- Journal dispatch verifies the original signed contract independently for each module/version. Legacy entries can recover from an exact matching installed release. Reinstalling the exact original release can repair a damaged retained contract. A different current release cannot substitute for the original schema.
- Invalid or unavailable contracts leave work pending with an explanation; invalid results are not retained as accepted receipts. Dependencies wait for acceptance, while unrelated entries continue. Foreign account/workspace entries cannot be dispatched or overwritten. Existing server permission checks and lease gates remain in force.

## Acceptance corrections and limits

The initial browser test assumed Contacts used immediate online writes while offline storage was enabled. Contacts deliberately journals its queued-policy changes in that configuration. The test now exercises immediate writes with offline storage disabled, then explicitly enables and warms the cache; a separate case verifies queued writes. It waits for completed validation failures before retrying and for durable cache writes before inspecting them.

Schema validation does not grant authority, guarantee chronology or make trusted client code a hostile-publisher sandbox. The retained key follows the existing local trust boundary; this does not protect against a compromised operating system. Full recovery of arbitrary online/custom operations across navigation, profile lock or process failure remains OFF-03/ID work. The archive retry in this milestone is scoped to the mounted generated screen. Signed release installation across supported operating systems, hosted providers, remote load acceptance and full accessibility retain their original gates.

GitHub Actions budget and artifact quota remain external remote-acceptance dependencies. These local passes do not substitute for an executed release CI run.
