## Next concrete gate: resource response validation

The gap is in `packages/module-sdk/src/index.ts`: `read<T>` and resource create/update/archive return typed casts of unknown transport values. Operations already validate their declared outputs, and reference lookups validate their page schema. Neither protects ordinary resource responses.

Acceptance requires schema-derived validation of record data and envelope metadata for get/create/update/archive, and every item plus cursor metadata for list. A malformed result must reject before it reaches typed callers or becomes a successful `useResourceList` page. Verify malformed metadata, incompatible returned data, malformed page entries/cursors, and valid responses across authoritative, simulator and standalone adapters. Preserve cancellation, idempotency and provisional-versus-accepted semantics; validation must not invent accepted mutation results or retry uncertain business effects automatically.

After that gate passes, re-audit this map against current evidence before marking SDK-04 verified. Do not infer completeness from a green narrow test, remove original requirements, or broaden SDK-04 indefinitely to absorb already-tracked UI/offline/platform work.
