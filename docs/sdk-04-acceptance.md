## Next concrete gate: generated host responses and journal acknowledgment

[Public SDK result validation](verification/resource-response/README.md) now checks every resource-client method, retains mutation keys and prevents malformed responses becoming successful custom-view pages. Operation/reference validators and inferred read-only query composition also have their scoped evidence.

The audit found separate direct-transport paths in `packages/app-web/src/module-view.tsx`: live get/list results are cast, cached pages are read without these schemas, and saves/journal submission can acknowledge raw responses. `syncModuleStorage` can submit work from other modules and retained versions, so the currently displayed module is not a sufficient validation contract.

Next acceptance: select the appropriate signed module/resource/version schema for each response, validate live and cached pages, preserve original request keys and uncertain mutation outcomes, and prevent invalid journal results from becoming accepted. Verify other-module entries and original-version requests, not only the currently open module. Keep existing authorization and lease gates, do not silently discard pending work, and do not invent an accepted business result.

Re-audit this map after that integration passes before marking SDK-04 verified. Broader UI/offline/capability/release work retains its original tracker rows; full parity remains unproven.
