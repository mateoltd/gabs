Execution status, priorities and acceptance gates live in the [parity tracker](parity-tracker.md). The [product vision](product-vision.md) preserves the approved scope and architectural decisions. Update this ledger alongside the tracker when implementation or evidence changes.

Mobile is explicitly deferred. STORE-001 and STORE-002 are referenced by the source but have no standalone definitions.

## Continuation evidence, 16 September 2026

`tests/module-services.test.ts` checks granted cross-module transactions, retry deduplication, typed rejection rollback, swallowed child-failure rollback and current actor permissions. Type checks reject invalid service inputs, events, configuration fields and undeclared operation permissions. `tests/module-simulator.test.ts` checks provisional offline work and revoked-permission synchronization. `tests/module-platform.test.ts` adds stock-count/version-pin, member-reference and actionable-notification acceptance. The browser suite exercises background installation, member assignment, structured addresses, stock counting and inbox decisions. See the current results in `docs/verification/README.md`.

This continuation closes concrete gaps; independent executable client/server loading and scoped migration orchestration now have local evidence. Complete lifecycle recovery, identity/recovery, background push, integrity lockdown, remaining LAN features and production acceptance are still unfinished.
