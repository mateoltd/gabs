# Requirement ledger

Execution status, priorities and acceptance gates live in the [parity tracker](parity-tracker.md). The [product vision](product-vision.md) preserves the approved scope and architectural decisions. Update this ledger alongside the tracker when implementation or evidence changes.

Server runtime acceptance for BACK-001/CORE-002 now includes [verified content reuse](verification/performance/verified-content/README.md): bounded exact-byte/signing-key caches, immutable hydrated contracts and release selection limited to each read-only snapshot. Warm-cache tests preserve revocation, tamper rejection and fresh command pins. This improves local performance evidence without closing OPS-07 or any outstanding requirement.

CORE-002/CORE-003 local lifecycle evidence now includes [durable verified downloads](verification/local-downloads/README.md): encrypted package-boundary recovery, original-account access for missing packages, offline review and atomic transfer into installation recovery. This does not close broader lifecycle, identity or release requirements.

SDK-02 is now locally verified within CORE-003: [the acceptance map](verification/local-versions/README.md) connects typed worker execution, capability boundaries, CPU cancellation, encrypted retry recovery, independent local packages and schema-safe lifecycle controls to current tests. SDK-03/04/05, identity storage/unlock, corporate import and broader release requirements remain open.

SDK-03 is now locally verified within typed framework acceptance: [the acceptance map](verification/module-services-preview/README.md) ties module-owned scenarios and independent checks to custom React previews, root/provider fixture reload, private stores, explicit services/grants and permission/offline simulation. SDK-04/05, real authority/durable execution and the complete fifth-module lifecycle remain open; broader requirement statuses are unchanged.

SDK-04 typed-framework evidence now includes [schema-derived module references](verification/module-documentation/README.md), CLI/build parity, stale-reference detection and compiled inferred usage examples. [Typed resource lists](verification/resource-lists/README.md) add inferred equality filters, composable tables, bounded paging, structured values and normalized offline caches. Recursive references, richer query controls and broader composability remain open.

EXT-04/05 received a [background lifecycle retry correction](verification/report-recovery/README.md#17-september-2026-bounded-background-lifecycle-retries) after the prior remote fleet failure. Local PostgreSQL, browser and minimized native recovery checks pass; fresh remote acceptance remains pending. No broader lifecycle or operational gate is inferred from this regression fix.

Baseline: [original Spanish functional specification](original-functional-spec.md), 29 defined IDs. The approved TypeScript/Electron/PostgreSQL/hybrid plan replaces the original execution and DRM approach. **This implementation expands the working product substantially, but the entire plan is not yet complete.** “Open work” is an implementation gap, not an approved scope reduction. Mobile is explicitly deferred. STORE-001 and STORE-002 are referenced by the source but have no standalone definitions.
